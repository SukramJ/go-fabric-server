from `main` at `a8ea503` (0.8.1). Release 0.9.0. Issue #60.

## §1 The bump — `2f4292f`

- go-fabric v0.20.0 → v0.21.0, go-fabric-ui v0.8.1 → v0.9.0 (no new module,
  notices unchanged); `make generate` moves the provenance only
  (`protocol/schema`). No compile break.
- `ble/bluez` (v0.12.1) and `ble/esphome` (v0.13.10) have no newer tag
  (`GOPROXY=direct go list -m -versions`): the ATT_MTU change of go-fabric
  #426 is not in a tagged `ble/bluez` yet, so it is not in this release.
- The Diagnostics tab comes with the bump: go-fabric-ui's `gofabric`
  adapter serves `Controller.SessionDiagnostics`, `DiagnosticEvents`,
  `DiagnoseMDNS` through `controllerSource`; `capabilities.diagnostics` is
  true (asserted in `TestControllerTelemetry`).

## §2, §3 Metrics and the flag — `a3a0b50`

- `controllerTelemetry` (`internal/daemon/run.go`) sets
  `controller.Config.Metrics = expvarmetrics.New("fabricserver.controller.")`
  and `Config.Diagnostics = diag.Diagnostics{Capacity: n}`; `Run` and the
  pages' test environment both call it.
- `--controller-diagnostics-capacity` (int, default 0 = go-fabric's 256);
  a negative value stops the start (`TestRunRefuses`), only with
  `--controller`.
- `internal/arch` admits `diag`, the type of `controller.Config.Diagnostics`.
- `TestControllerTelemetry`: capacity 3, one node commissioned; the trace
  holds 1..3 events, the diagnostics one peer, and `GET /metrics` every
  `contract.MetricNames()` key and the six controller names under the
  prefix. Observed: `aggregator.reassemblies`, `case.unresponsive`,
  `icd.checkins_missed`, `im.received`, `im.sent`, `mrp.retransmits`,
  `pair.failures`, `panics.recovered`, `pase.failures`, `pase.lockouts`,
  `reachability.probes`, `sessions.open` (=1), `subscriptions.active`.
- No add-on option: `addon/config.yaml` exposes no expert flag of this kind
  (`--node-limit`, `--bridge-result-timeout` are not options either); the
  environment variable works in the container.

## Questions

- The controller half's own metrics (`controllerapi.Options.Metrics`,
  prefix `fabricserver.`) go through the same expvar adapter, which
  publishes every `contract.MetricNames()` key at construction: `GET
  /metrics` therefore also lists `fabricserver.sessions.open`,
  `fabricserver.pair.failures`, … at `0` beside the controller's
  `fabricserver.controller.*`. Keep, or give the half a prefix of its own
  (`fabricserver.ws.` is what it writes) in a later bundle?
