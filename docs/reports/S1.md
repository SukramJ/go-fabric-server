## Protocol

- **Envelope** (`protocol/envelope.go`): `Request`, `Result`, `Error`
  (`status`, `cluster_status`, `reason`), `Event`; error codes 0–11 and
  100–103 with matterjs-server's names; the six commissioning reasons;
  `SchemaVersion` 14, `MinSupportedSchemaVersion` 11.
- **Codec** (`protocol/codec.go`): one encoder (no HTML escaping, `uint64` as
  plain digits), one request decoder (absent/`null` args → `{}`, a non-object
  → error 8 naming the command, a numeric `message_id` answered under its
  digits), `DecodeArgs` with `UseNumber`, `Uint64` for ids above 2^53 parsed
  from the literal (exponent, fraction, sign and strings refused). Fuzzed:
  `FuzzDecodeRequest`, `FuzzParseUint64`.
- **Backpressure** (`protocol/conn.go`): matterjs-server's
  `WebSocketConnection` translated (map 3459-3478, the clone's
  `WebSocketConnection.ts:60-310`). coder/websocket has no
  `bufferedAmount`; the socket's buffer is an in-flight list a writer
  goroutine drains, measured in bytes. Direct mode until the bytes in flight
  pass the high-water mark (1 MiB, ratcheting to twice the largest frame, at
  most 50 MiB); then an ordered outbox drained with a window;
  `SendReliable`, `SendOrdered(frame, droppable)`, `SendCoalescable(key,
  build)` (latest wins at the first position, built once when sent); cap
  max(1000, 20 × nodes); oldest droppable dropped; more pinned than the cap
  or a write without progress for 5 min closes the connection. Metrics
  through a `Metrics` interface `contract.Metrics` satisfies:
  `ws.connections`, `ws.queued_bytes`, `ws.dropped`, `ws.closed_overflow`.
- **Auth and transport** (`protocol/transport.go`, `internal/daemon`):
  `--listen host:port | unix:/path`, default
  `unix:$XDG_RUNTIME_DIR/fabric-server.sock`; `--token` checked as
  `Authorization: Bearer` or `?token=` on every route; a TCP listener beyond
  loopback without a token refuses to start; coder/websocket's origin check
  refuses a cross-origin browser handshake. `GET /health` (`{version,
  node_count, healthy}`), `GET /metrics` (expvar), `GET /schema`.

## Schema

`go run ./internal/gen` reads `parity.SchemaJSON()` of go-fabric v0.11.0
(Matter 1.6.1, matter.js `862ad75f`) and writes
`protocol/schema/tables_gen.go` (135 clusters with attributes, commands with
fields and their response, events with fields, features, struct, enum and
bitmap datatypes resolved through the cluster, its base and the global
datatypes; 91 device types; the global attribute ids the snapshot names;
camelCase property names by a port of matter.js's `camelize`) and
`protocol/schema/schema.json` (JSON Schema draft 2020-12 of the node data
values, `$defs/cluster.<id>` keyed by attribute id, the go-fabric version in
`x-go-fabric-version`). `internal/gen`'s test fails when the committed output
is stale, and CI regenerates and diffs. `internal/wire` renders and encodes
with these tables; the encoding itself is go-fabric's `spec.EncodeJSON`.

## Node cache

`controllerapi/cache.go`. One entry per commissioned node of the registry,
built at `Start` from the registry's nodes (their stored images; no events)
and refreshed from the client node's image whenever a hook fires (structure
hooks, `Changed`, `ConnectionStateChanged`, `Seeded`, `Commissioned`,
`Decommissioned`). A refresh re-renders only the clusters whose DataVersion
changed. `attributes` keyed `"endpoint/cluster/attribute"`, values through
`internal/wire` (tag-based, matterjs-server's rules); `available` is
`ConnectionState() == Connected`; `is_bridge` an Aggregator (looked up by
name in the schema) in any endpoint's DeviceTypeList, as
matterjs-server's `bridgeDetection.ts:28-38`; `date_commissioned` from
`Record().CommissionedAt`; `last_interview` the last `interview_node` (now,
when there was none, as matterjs-server); `interview_version` 6;
`matter_version` from BasicInformation SpecificationVersion, else estimated
from DataModelRevision (`ControllerCommandHandler.ts:193-215`);
`endpoint_parents` from `Endpoint.Owner()` for the endpoints in
`attributes` other than 0. Values of a node's first report after a start or
a commissioning are not sent as `attribute_updated`; the node becomes
available in a `node_updated`.

## Differences from the brief

- **go-fabric v0.11.0**: the work started on v0.10.9; the pin moved with the
  tag (go.mod, the generated schema), the guards ran again on it.
- **The in-process server does not run on `controller.New`**: it cannot take
  the site's network and clock (Q1-test). The tests drive
  `fabrictest.AddController`'s stack (the same registry and commissioner
  types) through a test backend whose `Pair` runs
  `fabrictest.Controller.CommissionNode` — the registry route
  `controller.Pair` runs — after checking the code against the device's own
  pairing codes.
- **An import below the facade, as a named exception**: `internal/wire`
  imports `cluster/spec` and `tlv` (Q1); the guard names it and refuses it
  everywhere else. Also allowed, as "what controller exposes":
  `controller/commissioner`, `controller/attestation`, `client/discovery`,
  `client/exchange`, `client/handshake`, `client/interaction`, `client/peer`,
  `node/metrics/expvar`, and `controller/dcl/snapshot` (Q10).
- **Attribute values are tag-based, not name-based**: the brief (§3) and
  concept C.2 say "name-based for known clusters"; matterjs-server sends
  attribute structs keyed by field id (`Converters.ts:489-490`, map 2551, and
  its own `bridgeDetection.ts` reads `entry["0"]`). Compatibility first;
  names are used for command responses and event data, as matterjs-server
  does.
- **`is_bridge`** is an Aggregator on any endpoint (matterjs-server's rule),
  not "on endpoint 1".
- **Seven S1 commands have no facade route** (Q3, Q4, Q5, Q7, Q9): they answer
  `InvalidCommand` naming the route and are absent from `capabilities`; each
  has a test of that answer, and `commission_on_network`/`discover` run end
  to end with the test backend.
- **Dependencies**: `github.com/coder/websocket` is ISC-licensed, not MIT
  (permissive, recorded in `THIRD-PARTY-NOTICES.md`); `modernc.org/sqlite` is
  a direct dependency (Q11) — already in the graph through go-fabric.
- **`release.yml`** carries the release matrix and the ghcr image; the
  sibling's file name is `release-on-tag.yml`.
- **The read map's `read_attribute "1/6/0"`** is `"2/6/0"` here: fabrictest
  puts the light below the Aggregator on endpoint 2.

## Decisions

- **D1** The facade gaps are routed through optional interfaces
  (`Discoverer`) or answered `InvalidCommand` with `details: "not implemented
  in go-fabric-server <v>; needs <route> in go-fabric"` — a command starts
  working the moment go-fabric offers its route, without a protocol change.
- **D2** One hook set per node when the backend allows it
  (`Server.Hooks(id)` as `RegistryConfig.HooksFor`); with
  `controller.Config.Node.Hooks` (Q2) a change refreshes every node.
- **D3** Events are emitted under the server's lock, and `start_listening`
  holds it while it builds the dump, hands the answer to the socket and
  switches the connection on: no event between the dump and the switch.
- **D4** `write_attribute`'s result keeps the documented PascalCase
  (`Path`/`EndpointId`/`Status`, docs/websockets_api.md:612; the snake_case
  `AttributeWriteResult` of model.ts:1498 is `set_acl_entry`'s, map 1498).
- **D5** Epoch values go raw: matter.js decodes them to Unix time and
  matterjs-server subtracts the offset again (Converters.ts:466-472).
- **D6** A commissioning outlives the connection that asked for it (5 min,
  or `discovery_timeout_s`): a half-done commissioning leaves a fail-safe
  armed.
- **D7** The server's own settings (credentials, label) live in
  `server.json` (0600) under `--storage-path`, apart from the controller's
  database.
- **D8** The image and the unit listen on `127.0.0.1:5580`, the URL Home
  Assistant's integration uses on the same host (its add-on runs with host
  networking); the bare binary defaults to the Unix socket, as the brief
  says. Home Assistant sends no token, so it must be on loopback.
- **D9** A missing or malformed `node_id` is `InvalidArguments` for every
  command (python-matter-server's behaviour).
- **D10** `--health-check URL` in the binary serves the image's
  HEALTHCHECK (distroless has no shell).
- **D11** The brief's `server: "go-fabric-server/<v> (go-fabric/<v>)" in
  sdk_version's form` is read as the value of `sdk_version`
  (`go-fabric-server/0.1.0 (go-fabric/v0.11.0)`), matterjs-server's form
  `matter-server/<v> (matter.js/<v>)`; no extra `server` key.

## Left out

- `attribute_names` in the node data and a `get_schema` command (concept
  C.2's extensions): they double every `node_updated`; better as an opt-in of
  `start_listening` in S2.
- Group Node IDs (groupcast `write_attribute`/`device_command`) and the node
  id class checks (matterjs-server's error 8 for CAT, PAKE and reserved ids).
- chip's acronym-preserving alias next to the property name in name-based
  structs (matterjs-server's `matterNameToWireField`, wire-naming.ts).
- Using the stored Wi-Fi/Thread credentials: `controller.Pair` commissions
  over DNS-SD only (Q14).
- `write_attribute` updating the node data before the device reports.
- A file log (`file_loglevel` is `null`); the dashboard (concept: never in
  the protocol).
- The bridge half (`bridgeapi` is a placeholder for S2).

## Questions — facade gaps (go-fabric symbol needed, why)

- **Q1-test** `controller.Config` takes `Listen string` and `Names func`, but
  no listener/exchange manager and no clock, so `controller.New` cannot run
  on a `fabrictest.Site`. Needed: `controller.Config.Transport` (or
  `Exchanges`) and `controller.Config.Clock`, or `fabrictest.Site.ControllerConfig()`
  returning a `controller.Config` wired to the site.
- **Q1** No value codec on the controller facade: `client.Cluster.Value`,
  `client.AttributeData.Value`, `client.Result.Fields` and
  `client.EventData.Value` are `spec.Node` trees, and `Write`/`Invoke` take a
  `spec.Encodable`; reading or building one needs `cluster/spec` and `tlv`.
  Needed: `client.DecodeJSON(field, node)` / `client.EncodeJSON(field, raw)`
  in the protocol's forms (tag- or name-based structs, base64 bytes), or
  aliases of `spec.Node`, `spec.EncodeJSON`, `spec.Field`/`Type`/`Kind` and the
  TLV element kinds in `controller/client`.
- **Q2** `controller.Config.Node.Hooks` is one hook set for every node;
  `client.RegistryConfig.HooksFor` exists, but `controller.Config` does not
  expose it. Needed: `controller.Config.HooksFor func(id string) client.Hooks`.
  Without it `node_event` cannot be attributed to a node and is not forwarded
  in production.
- **Q3** No discovery on the controller: `controller.Controller` keeps its
  `discovery.Names` private. Needed: `Controller.Discover(ctx, discovery.Identifier,
  timeout) ([]client.Device, error)` (fabrictest.Controller has it) — for
  `discover_commissionable_nodes`, `discover`, `commission_on_network` and a
  fresh `get_node_ip_addresses`.
- **Q4** No exported onboarding payload decoder (`secure/setup` is below the
  facade), and `controller.Pair` wraps a decode failure without a sentinel.
  Needed: `controller.ParsePairingCode(code)` (QR payloads, manual codes:
  version, vendor, product, flow, capabilities, discriminator, passcode) and
  `controller.ErrPairingCode`.
- **Q5** No commissioning window route: needed
  `client.Node.OpenCommissioningWindow(ctx, timeout) (Window{Passcode,
  Discriminator, QR, Manual, VendorID, ProductID}, error)` (the reference
  CLI builds it from `secure/spake2` and `secure/setup`).
- **Q6** An attestation rejection is a `commissioner.CommissioningError` with
  kind `ErrCommissioning` and a message only. Needed:
  `commissioner.ErrAttestationRejected` (reason `attestation-rejected`).
- **Q7** `client.Node.Invoke` sends one command. Needed:
  `client.Node.InvokeBatch(ctx, []CommandRequest, InvokeOptions) ([]Result,
  error)` and the node's MaxPathsPerInvoke.
- **Q8** No run-time fabric label: needed `Registry.SetFabricLabel(ctx,
  label)` (or `Fabric.SetLabel` plus the registry's reconciliation, today
  internal in `client/label.go`).
- **Q9** No per-node switch of the default subscription: needed
  `client.Node.SetAutoSubscribe(ctx, on bool) error`.
- **Q10** No production trust store in one call: the daemon builds it from
  `controller/dcl/snapshot.Embedded` and `attestation.Trust`. Needed:
  `attestation.Production()` (or a `controller.Config` default).
- **Q11** `controller.Config.DB` makes the host pick and import a SQLite
  driver; the daemon imports `modernc.org/sqlite`. Needed:
  `controller.OpenDB(path)` (or a store opener in the facade).
- **Q12** The `matter_version` string decodes SpecificationVersion's bytes
  by hand (as matterjs-server does); a `client.Properties` field with the
  decoded version would remove it.
- **Q13** No reading of a Thread operational dataset (network name, extended
  PAN id) for `get_all_credentials`' summaries. Needed: e.g.
  `commissioner.ParseThreadDataset(b)`.
- **Q14** `controller.Pair` finds devices over DNS-SD only; BLE commissioning
  (ADR 0024) is not on its route. Needed: `controller.PairOptions.BLE` (or a
  channel) so `commission_with_code` without `network_only` can use the
  stored credentials.

## by_design candidates (deviations from matterjs-server's wire behaviour)

- **B1** `ping_node` answers each address with the outcome of a Matter read,
  not of ICMP echoes (matterjs-server `ControllerCommandHandler.ts:2261-2300`;
  docs map 1795-1806): no raw sockets in a non-root distroless daemon.
- **B2** A missing or non-numeric `node_id` is `InvalidArguments` for every
  command; matterjs-server answers `UnknownError` for the node-targeted ones
  (map 4196-4201).
- **B3** A `node_id` of a class that can never name a node (group, CAT,
  reserved) is `NodeNotExists`, not `InvalidArguments` (map 4202-4211).
- **B4** Path ids are checked by width, not by matter.js's id classes
  (map 2382-2383).
- **B5** Name-based structs carry the property name only, not chip's alias
  (map 2504-2516).
- **B6** `write_attribute` does not update the node data before the device's
  report (docs/websockets_api.md:604-606 of the clone).
- **B7** `get_all_credentials`' Thread entries carry only `id` (map 1504).
- **B8** `set_default_fabric_label` is stored, not pushed to the nodes
  (map 1523).
- **B9** `get_matter_fabrics` carries no `vendor_name` (DCL vendor names are
  S2's `get_vendor_names`).
