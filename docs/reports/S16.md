## Decisions

- `primed` latches on go-fabric's Connected (note: approximation of the
  subscription latch, recorded in `docs/protocol.md`).
- `Start` marks entries restored by passing `&nodeState{restored: true}`
  as `prev` to `snapshot`, so one code path computes both.
- The rotation keeps a per-run set of resealed node files, so an erase's
  restart does not try `node.Reseal` again.
- Two key files with the same key are refused ("nothing to rotate").
- `explain` maps both node and controller errors through
  `controller.ErrUnseal`/`ErrNoSealer` (the same `store` values,
  `controller/seal.go:11-19`, `node/facade.go:113-122`).

## Questions

1. **#75, facade gap (*Work that needs go-fabric*).** go-fabric's own test
   makes a load-failed node by writing a malformed record field with
   `controller/client/sqlstore.New(db).Save` and a `tlv` encoder
   (`controller/ota_node_deleted_unavailable_test.go:58-66` at v0.28.0);
   neither package is in `internal/arch`'s facade or `testOnly` list, and
   `fabrictest` has no helper. Needed in go-fabric: a facade-level way for
   a host's test to produce a node that fails to load (e.g. a `fabrictest`
   helper corrupting a stored node). Until then the `remove_node` change
   would ship untested. **Owner, 2026-11-27: wait** — handed over as
   thingfabric/go-fabric#639; #75 stays open until it lands.
2. **#81 item 6, `update_node` gate.** Not applicable: `update_node` is not
   implemented (`controllerapi/dispatch.go:105`, `planned` → `otaRoute`);
   there is no gate to align. When the OTA route lands it should refuse an
   unavailable node as `ControllerCommandHandler.ts:2765-2769`.
3. **#81 measurement, `node_added`.** On commissioning, `node_added` goes
   out from the node's first cache refresh, measured while the node is not
   yet started (`available:false`); the answer itself carries `true` and a
   `node_updated` with `true` follows. Review (Fable): matterjs-server
   sends `node_added` and the answer with the same `available`
   (`ControllerCommandHandler.ts:2114`, `:2119`;
   `WebSocketControllerHandler.ts:515-519`, `:1357`); here
   `Hooks.Commissioned` fires before `n.Start`
   (`controller/client/fabricops.go:273-277`). Recorded as a difference in
   `docs/protocol.md`, to align later (low); code unchanged.
4. **Step-5 measurement.** `controller.Reseal` on a never-sealed
   controller database: `ErrUnseal` (it holds its CA in clear; the godoc's
   "a secret in clear"), the open under the new key then seals it.
   `node.Reseal` on a never-sealed, uncommissioned node store: **nil** —
   it moves to the new key without error. Both pinned in
   `TestResealNeverSealed`.
5. **F9 measurement.** `node.New` without a sealer on a commissioned
   sealed node store **fails** with `ErrNoSealer` (loading the group key
   sets: `node: group state: groups: load key sets of fabric 1: … the value
   is sealed and the store has no sealer`). No facade gap for a
   commissioned node; an uncommissioned sealed node store still opens
   without a sealer (go-fabric's own test, F9). Pinned in
   `TestSealedNodeStore`.
6. **Topology `available`** stays Connected-only (go-fabric
   `controller/topology/image.go:68`); whether matterjs-server's topology
   differs is open (recorded in `docs/protocol.md`).
7. The systemd example was removed in review (see §4).
