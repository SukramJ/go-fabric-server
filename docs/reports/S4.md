- **`internal/daemon/web.go`**: `webHandler` takes a
  `fabricui.ControllerSource`; `Options.Controller` is set when the
  controller half runs and `--web` is given. A nil source shows the family

- **`internal/daemon/controllerui.go`**: `controllerSource` =
  `gofabric.ControllerOf(ctrl, gofabric.ControllerOptions{Hooks,
  Credentials, Pair, Logger})`, wrapped so `SetFabricLabel` goes through
  the controller half. `credentialStore` adapts the half's `server.json`
  store to `gofabric.Credentials` (`fabricui.CredentialStore` + `WiFi`/
  `Thread`), and maps the half's errors to `ErrInvalidCredential` /
  `ErrUnknownCredential`.
- **`controllerapi/host.go`** (new exported surface): `Credentials`,
  `SetWiFiCredential`, `SetThreadDataset`, `RemoveCredential`,
  `WiFiCredential`, `ThreadDataset`, `SetFabricLabel`, `PairOptions`, and
  the errors `ErrInvalidCredential`, `ErrUnknownCredential`,
  `ErrLabelPinned`. Each change has its WebSocket command's effect,
  `server_info` broadcast included. `PairOptions` is the half's
  attestation policy, its `--disable-auto-subscription` mode and the BLE
  central of `--bluetooth-adapter`, which is also the status'
  `capabilities.ble`.
- **Events / hooks**: `run.go` builds `gofabric.NewHooks()` and sets
  `cfg.HooksFor = pageHooks.Wrap(api.Hooks)` before `controller.New`.
  `Wrap` chains, it does not replace: every hook of `api.Hooks(id)` runs
  first, then the stream's, and `Event` (node_event) stays the half's
  only. The node family's events are unchanged. On shutdown
  `pageHooks.Close()` runs before `ctrl.Close`.
- **Admin**: one `Options.Admin` for both families, so the controller's
  `x-admin` routes follow `--web-admin` / `--web-admin-source` exactly
  like node writes. The Ingress form (`--web-admin-source 172.30.32.2`) is
  unchanged.

## Differences from the brief

- The adapter's options type is `gofabric.ControllerOptions`, not
  `gofabric.Options`.
- **The release was blocked on armv7** by go-fabric-ui v0.2.0 (Q1), and is
  unblocked by the re-pin to v0.2.1.
- The pages' label change goes through the controller half
  (`controllerapi.Server.SetFabricLabel`) instead of the adapter's own
  `Fabric().SetLabel`. Without that, the next start would push the
  `server.json` label back, and `--default-fabric-label` would not hold.
- With a branch-head go-fabric-ui, an early run panicked: a coalescing
  `node_updated` timer fired after `Controller.Close` had set the registry
  to nil. v0.2.0 fixed this with `Hooks.Close`, and the daemon calls it.
  The interim workaround (a hook gate) was removed before the commit.

## Decisions

- **D1** The pages do not claim the fabric label against a `/ws`
  connection that owns it (`set_default_fabric_label`'s first-connection
  rule). The Ingress user is an administrator, and the label is stored
  either way.
- **D2** The pages' list shows stored entries only. `get_all_credentials`'
  placeholder `default` entries are left out. An id-less `/ws` set stores
  `default`, and that entry then appears on the pages.
- **D3** Removing an unknown credential is 404 on the pages, while the
  commands succeed without effect (the contract's 404 fixture).
- **D4** The page hooks are wired only with `--web`; without it the
  daemon's hook set is exactly v0.3.2's.

## Left out

Out of scope per the brief: the add-on Bluetooth option (after the owner's
BLE test), the Thread border-router commands (go-fabric milestone 6 wave
26a), and removing `Item.Fields`' comma form (go-fabric-ui v0.2.1; the
daemon uses no `Exposure`, so it is unaffected).

## Questions

- **Q1** (answered: fixed in go-fabric-ui v0.2.1, pinned here) go-fabric-ui v0.2.0 does not compile for 32-bit targets: `int`
  compared with `0xFFFFFFFF` at `fabricui/handlers_controller.go:1135`
  (the discovery filter value) and `:1316` (the update consent's
  `TargetSoftwareVersion`). That blocks go-fabric-server's linux/arm/v7
  release archive and its armv7 add-on image. Recommendation: fix it in
  go-fabric-ui v0.2.1 (compare as `int64`, or use a typed `uint32` in the
  contract), add a `GOARCH=arm` build to its CI, and re-pin here before
  v0.4.0 is tagged. This PR can merge first, since its CI does not build
  armv7.
- **Q2** (filed as go-fabric issue #291) U2's Q3 also applies here: go-fabric has no commissioning-progress
  hook and no `softwareupdate.Manager` observer, so the pages'
  `commissioning_progress` and `update` events come only from the handler.
  Recommendation: the go-fabric CK issue U2 proposed.

## by_design candidates

None. The pages add no wire behaviour to `/ws`.
