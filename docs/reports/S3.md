## §2 The JSON route replaces `internal/wire` — `ae77f3c`

Every read, write, invoke, event and subscription value goes through
`client.EncodeJSON`/`DecodeJSON` (`controllerapi/values.go`); the path
parser moved to `controllerapi/paths.go`; `internal/wire`, its tests and
its arch exception are deleted (the exceptions map is empty, the self-test
refuses `tlv` for `controllerapi` and `internal/wire`); `make fuzz-smoke`
runs `FuzzParsePath` and `FuzzEncodeFields` in `controllerapi`. Nothing
generated was edited. The 88 documented fixtures pass unchanged (their
check is a round trip through the server's types, equal modulo key order
and the documented extensions); five of the formerly skipped shapes are
now checked, five remain skipped (OTA, Thread diagnostics, WebRTC, the two camera events).

Findings of the switch:

- **16 clusters are untyped on the route** (Q20): `client.AttributeField`,
  `CommandField`, `ResponseField`, `EventField` type only clusters with a
  `cluster/spec` definition. For AccessControl, OperationalCredentials,
  GroupKeyManagement, the Thread, camera, TLS and Joint Fabric clusters
  they are untyped, so `set_acl_entry`, `get_matter_fabrics` and
  `remove_matter_fabric` broke at first (names refused, names missing).
  The server shapes the untyped form by `protocol/schema` for exactly those
  clusters (re-key by name or id on the way out; decimal ids and chip's
  `base64:`/`s:`/`f:`/`d:` prefixes on the way in), and a typed field is
  never reshaped, so the fallback goes when go-fabric types the clusters.
- A 4-byte float now renders as its shortest decimal (`0.1`), where
  `internal/wire` and matterjs-server print the double expansion (B18).
- A command's mandatory field left out takes matter.js's fallback
  (`client.EncodeJSON`), where `internal/wire` refused it.
- `DecodeJSON` marshals with HTML escaping (`<` as `<` inside
  strings); equal JSON, different bytes from before.

  `NetworkTopology` from the node data — nodes (`network_type` from the
  root's NetworkCommissioning FeatureMap; Thread role, ext address, RLOC16,

## Differences from the brief

- **`commissioner.ParseThreadDataset` does not exist**: go-fabric's CJ
  report answers 1.13 with `controller/thread.DecodeDataset` ("exists and
  is the one shape", `notes/briefs/reports/CJ.md:131`). The server uses
  `controller/thread`, added to the import guard's facade list.
- **BLE is wired but cannot be built**: `controllerapi.Options.BLE` takes a
  `ble.Central` and `commission_with_code` uses it; the daemon's
  `--bluetooth-adapter` refuses to start, because go-fabric's BlueZ module
  has no release on v0.12 (Q22). No BLE in CI, as the brief says.
- **Test-node writes are not refused**: matterjs-server answers a test
  node's `write_attribute` with status 0 and writes nothing
  (TestNodeCommandHandler.ts:190-202); the server does the same.
- **`node_diagnostics` is not a command** (above).
- **The fixtures of the new shapes** live in
  `protocol/testdata/compat/python/` (eleven files, README with the
  models.py lines), apart from the extractor's output.
- **The add-on has `bridge`/`bridge_port` and `enable_test_net_dcl`**
  besides `port` and `log_level`: the node pages need the bridge role, and
  devices with test certificates need the test roots.
- **The bridge half's Identify** (S2 Q16) is accepted now; the test that
  held its refusal checks the declaration and the refusal of anything else.

## Decisions

- **D1** The Q20 fallback shapes go-fabric's untyped JSON by our generated
  tables instead of answering `InvalidCommand`: `set_acl_entry`,
  `get_matter_fabrics` (Home Assistant's `node_diagnostics`) and
  `remove_matter_fabric` worked in v0.2.1 and Home Assistant calls them;
  the fallback reads no TLV and goes when the clusters are typed.
- **D2** `commission_on_network` discovers in 2-second rounds: one
  `Controller.Discover` returns only at its timeout (3 minutes by default).
- **D3** `batched_device_commands` refuses more commands than the node's
  MaxPathsPerInvoke, although `InvokeBatch` could split them: the python
  client documents "never split".
- **D4** The attestation policy is `Reject` (go-fabric's default) and
  `--enable-test-net-dcl` widens the trust, as matterjs-server; tests on a
  `fabrictest` site accept the site device's findings
  (`attestation.TestStore` does not accept test certificates).
- **D5** Test nodes are listed after the real nodes, take part in
  `get_network_topology` and count in `/health`'s `node_count`.
- **D6** `network_topology_updated` is computed after each cache pass and
  test-node change, sent only when its hash moved, coalesced per
  connection.
- **D7** The label push runs in the background with a 2-minute bound; a
  newer label cancels an older push; `Shutdown` waits for it.

## Questions

Go-fabric facade gaps (symbol needed, why):

- **Q20** The JSON route types only clusters with a `cluster/spec`
  definition: `client.AttributeField`, `CommandField`, `ResponseField` and
  `EventField` are untyped for AccessControl, OperationalCredentials,
  GroupKeyManagement, ThreadNetworkDiagnostics, ThreadBorderRouterManagement,
  ThreadNetworkDirectory, ZoneManagement, CameraAvStreamManagement,
  CameraAvSettingsUserLevelManagement, WebRtcTransportProvider,
  WebRtcTransportRequestor, PushAvStreamTransport, JointFabricDatastore,
  JointFabricAdministrator, TlsCertificateManagement and
  TlsClientManagement. Needed: definitions for them (or `client.*Field`
  typed from the parity snapshot where no definition exists), so
  `set_acl_entry`, `get_matter_fabrics`, `remove_matter_fabric` and their
  events need no server-side shaping (D1).
- **Q21** `controller.Controller.Discover` returns only when its timeout
  passes; a commissioning that wants the first matching device waits the
  whole window. Needed: a first-match form, e.g.
  `Controller.DiscoverFirst(ctx, id, timeout) (client.Device, error)` or a
  callback that ends the search — matter.js's `commissionNode` stops at
  the first answer (CommissioningController.ts:462-500 at 862ad75f).
- **Q22** `github.com/SukramJ/go-fabric/ble/bluez` has no release on
  go-fabric v0.12: v0.7.0's tests import `controller/discovery`, which
  v0.12.0 moved to `client/discovery`, so `go mod tidy` in a consumer
  fails. Needed: a `ble/bluez` tag on v0.12.x; then
  `--bluetooth-adapter` passes `bluez.NewCentral` to
  `controllerapi.Options.BLE` (the code path is there).
- **Q23** `client.DecodeJSON` marshals with HTML escaping (`<`, `>`, `&` as
  `\u003c` …). Needed: an encoder with `SetEscapeHTML(false)`, the bytes
  matterjs-server's JSON writes; equal JSON either way.
- **Q24** Is a `client.Device` built from a bare address (no DNS-SD
  answer) a supported input of `client.Registry.ForDevice`? It would let
  `commission_on_network` commission at `ip_addr` first, as matterjs-server
  does (B16); without a documented route the server discovers.

matterjs-server shape questions:

- **M1** Home Assistant pins `matter-python-client==1.4.0`, a schema 11
  client (`SCHEMA_VERSION = 11`) without methods for
  `parse_onboarding_payload`, `batched_device_commands` and the
  subscription commands, whose `commission_on_network` takes no filter;
  the a7922e85 client has them. The integration therefore cannot reach
  those commands until core moves its pin.
- **M2** `next_expected_checkin`'s unit is epoch milliseconds by the model
  comment and the documented example only (model.ts:1884); the server
  sends Unix milliseconds.
- **M3** An `import_test_node` dump that is not JSON: matterjs-server's
  parse error is not caught in the handler (TestNodeCommandHandler.ts:125)
  and answers 0; the server answers 8 `Invalid dump format: …` like the
  other dump errors. Kept unless the owner wants 0.

  maximum).
