## §2 `fix(bridgeapi)` — `d4f4c8b` (row 5)

- `replace`: a served device is replaced in one step by `Batch.Replace`,
  whether its successor is served or withheld (go-fabric #585,
  `CHANGELOG.md:151` at v0.26.0, `node/aggregator.go:696-805`); a
  withheld predecessor holds no place in the set, so its successor is
  added. S14's Remove + Add + Forget and the `gone` / `removedGone` half
  state are gone. A refused replacement leaves the served device served
  and declared, its entry carrying the `error`.
- Commit-time errors (`CHANGELOG.md:72` at v0.26.0,
  `node/aggregator.go:523-617`): `commitErrors` sorts the `Batch` error's
  leaves into withheld declarations (`*surface.WithheldError`, by key — no
  error), key refusals (`ErrDuplicateKey`, `ErrUnknownKey`,
  `ErrReservedKey`, `ErrPolicyMismatch`) and the rest. After the batch,
  each added or replaced device is judged by what the node holds: served
  (`Aggregator.Endpoints`) or recorded withheld (at the call or at the
  commit). A device neither is refused at the commit: its entry carries
  `the node refused it when the batch committed: <refusals>`, an added one
  is not declared, a replaced one leaves its predecessor declared. A key
  the batch could not forget (still served) stays declared. Only a commit
  error that is no key refusal, or a key refusal no device carries,
  answers `UnknownError` (`declare: the node's batch: …`), with the map
  already reconciled.
- `took` / `logWithheld` replace `add`; a `batchReplace` seam beside
  `batchAdd` (`export_test.go` `SetBatchReplace`).
- `docs/protocol.md` `declare`: the one-step replace and the commit-time
  refusal; `changelog.md` Fixed.

## §3 `test(controllerapi)` — `c5631d5` (row 6, #78)

Cause: `commission_with_code` answers before the node's subscription is
up — the answer and the cache entry say `available: false` (probe: 3 of 3
runs). The cache sends `attribute_updated` only for a node already
`primed` (`cache.go:395`; primed once a refresh saw it available,
`:92-94`, after `docs/websockets_api.md:2065`). The hooks' marks are
coalesced (`cache.go:304-324`): when the `ConnectionStateChanged` refresh
and the refresh of the On report fall into one pass, or the On lands in
the priming report, the change goes out as `node_updated` only, and the
test's 30 s wait for `attribute_updated` times out. Not a lost report: the
value is in the `node_updated`. Red: a probe that sends On right after the
commissioning answer failed 5 of 10 runs. Fix in the harness:
`env.commission` waits for the node to be available (`waitAvailable`,
polling `get_node`, which also refreshes and primes the entry) when the
server subscribes on its own (`DisableAutoSubscription` unset). Proof:
the probe and `TestCommissionReadCommandAndEvents` 30 times each under
`-race` (60/60 pass, no race); the same probe without the wait had failed
half the runs. The original test passed 160 of 160 runs under `-race`,
four processes at once with `-cpu 1` and load average ~10, before the fix:
the window is narrow in the real test. Also covers the `batched_device_commands`
subtest of `TestCommands`, which waits for `attribute_updated` the same
way. No code change, no changelog entry.

## Better than others, better than before, the right cut

- **Better than others.** matterjs-server's bridge has no declaration
  door to compare; against go-fabric's reference daemon the half reports
  a commit-time refusal per device instead of failing the document.
- **Better than before.** A served device replaced by a withheld one no
  longer passes through a state where the key is off the node and the
  half's answer must list it in `removed`; a refusal the node makes at the
  batch's commit no longer leaves the half believing a device it does not
  serve, nor makes a later declaration forget another endpoint's key.
- **The right cut.** The atomic replace and the end-state judgement are
  go-fabric's; the half only follows the node's set. The label cut at load
  is go-fabric's (#587); the server keeps only `server.json`'s own cut.

## Decisions

- A commit-time refusal is a per-device `error`, not an error code for
  the whole `declare`; only a non-key commit error (store, reassembly,
  attach) or an unclaimed key refusal stays `UnknownError`.
- A device refused at the commit gets every key refusal of the batch in
  its `error`: go-fabric's errors name the colliding key, which can be a
  part key, so attributing them by key would parse error text.
- The half's map is rebuilt from `Aggregator.Endpoints()` and the withheld
  records after every batch, also on the `UnknownError` path.
- #78: the test waits for the condition (availability); the cache's
  primed rule is unchanged.
