## §6 #54 — `f897d5c`

Measured: with go-fabric v0.19.1 `TestTwoNodes` missed the drop in about
one run of three (at v0.7.0: 0 of 6). The debug log of a missed run has the
Leave report answered (`matter.tx.subscribe.event_report.flush_answered`)
and the controller logging `registry.peer_left`, and the controller's
registry held no node: `get_nodes` listed a node the controller had
deleted. The server refreshed on `Decommissioned`, which go-fabric runs
before `deleteNode`, and no hook follows the deletion. Fix: the server drops
a node on its `Decommissioned` hook (`Server.left`), as matterjs-server
does (`ControllerCommandHandler.ts:941-947`, `:2347-2368`). The test waits
10 s; past it, it asserts that the controller still holds the node and that
the erased node holds no session and no subscription. 15 of 15 runs pass
after the fix.

## Differences from the brief and the issues

- #56 (c): `camera_wire.go` is not deleted — it holds the result shapes and
  the argument decoder; only its name copies go. `TestWireNames` goes;
  go-fabric's `wire_names_parity_matterjsserver_test.go` holds the names.
- `cameratest` has no hold of an offer and no counted refusal:
  `TestCameraStartHoldsUntilResponse` and `…RegisteredInArrivalOrder` send
  the candidates right after the start without a gate (the queue's limit and
  cancel stay in `camera_events_internal_test.go`); `TestCameraStreamEvicted`
  clears the allocation refusal from the env's `onEvicted` hook (the
  eviction path, before the retry); the in-use release refuses stream 1.
- `ParseICECandidates` wording: an empty list is "ice_candidates must be an
  array of 1 or more entries"; a key spelled twice is no longer refused.
- #54: the brief assumed a lost Leave; the measurement showed a server cache
  bug, fixed here besides the bounded assertion.
- The erase sentence of `docs/operations.md` landed in `058ee58`.

## Decisions

- `thread/brdiscovery` is a facade package (the type of a controller
  method), not a test-only import.
- A decommissioned node stays hidden while the registry still holds it (a
  failed deletion), as in matterjs-server.

## Left out

- `get_thread_border_routers`: `brdiscovery.Entry` lacks `addresses` and
  `sources` (required in matter.js `BorderRouterEntry.ts:15-54`), the
  meshcop and TREL ports and the TXT `tv`, `sv`, `rv`, `dd`/`ai`, `sb`,
  `at`, `pt`, `dn`; and `hostname` is the raw FQDN there.
- An add-on option for the mDNS interfaces.

## Questions

- go-fabric (#54's question, not filed): in about half the runs each erase
  takes ~14 s: after the Leave event report is answered the controller tears
  its subscription down, the attribute report flushed after it is never
  answered, and `FactoryReset` waits the full chunk StatusResponse bound
  (`matter.tx.subscribe.report.flush_unanswered timeout=14.051s`). The
  bounded wait for the Leave's report exists (`awaitFlushedReport`, since
  v0.17.0); the open point is the wait for the reports after it.
  [Fixed in go-fabric 0.19.2 (#473): the flush sends one report and waits
  at most 500 ms; S10 measured the drop at about 20 ms.]
- `cameratest`: an offer hold and a counted refusal would let the two queue
  tests prove the queue end to end again.
