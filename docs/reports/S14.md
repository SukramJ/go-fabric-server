## Better than others, better than before, the right cut

- **Better than others.** matterjs-server masks arguments by a list of
  field names; this server judges them by the model's isSecret marks, so a
  secret the list does not name cannot escape, and an unknown shape fails
  closed. `/metrics` publishes no command line.
- **Better than before.** The fabric label and the NodeLabel are cut where
  go-fabric now refuses — set labels, the pin (refused, naming the flag)
  and a `server.json` of 0.10.0 (cut at load); a fabric record of 0.10.0
  beyond 32 bytes still stops the start until go-fabric #587; a refused
  `host` statement is an answer, not a silent drop; the pages refuse a
  foreign `Host` (DNS rebinding) and the stop no longer waits 5 s.
- **The right cut.** The marks and the label caps are go-fabric's
  (`protocol/schema` generated, `device.ComposeNodeLabel`); the host check
  and the rights are go-fabric-ui's; the server only wires them and keeps
  the add-on's admission (the source address). Sealing waits for a facade
  route in go-fabric (Appendix A).

## Decisions

- `--bridge-label`'s bound is tested through `device.ComposeNodeLabel`
  (no 32 of our own in the check; the message names 32 bytes).
- `replace` reports `gone` through an unexported field of the result.
- The stored label is saved back after the cut (not only cut in memory),
  so the Warn appears once.
- The SDP mask applies to every string the argument log shows, not only
  to a member named `sdp` (matterjs-server's scope): a superset.
- The ICE server's `Username` has no isSecret mark and is logged;
  matterjs-server masks it (`logging-redaction.ts:56`). Left to the model.

## Work that needs go-fabric (ready to file; filed as go-fabric #584)

**Title:** A sealer a host can build through the facade (`store.NewAESGCMSealer` is below it)

- **Why.** go-fabric-server (a host that imports go-fabric through its
  facades only, guarded by its `internal/arch`) wants to seal the
  controller's database once `controller.Config.KeepOnboardingCodes` puts
  one setup code per node into it (go-fabric-server #70).
  `controller.Config.Sealer` (`controller/controller.go:159-182`) and
  `node.Store.Sealer` (`node/config.go:799-813`) take a `store.Sealer`
  (`store/seal.go:35-41`); the only implementation the module ships is
  `store.NewAESGCMSealer` (`store/seal.go:57`), in a package of the
  `security-and-storage` layer (`script/archcheck/layers.json:6`), not of
  the facade (`:11`). A facade-only host can name the option but not fill
  it without importing below the facade or writing its own AEAD wrapper.
  All lines at v0.25.0.
- **Scope / shape (go-fabric decides).** A facade route to the stdlib
  sealer and its type — e.g. `node.NewAESGCMSealer(key)` beside the store
  errors `node/facade.go:96-105` re-exports, usable for
  `controller.Config.Sealer` too — and the errors a host must tell apart
  at start (`store.ErrUnseal`, `store.ErrNoSealer`) reachable for
  `errors.Is` from the controller facade; `controller.Reseal`
  (`controller/reseal.go:39`) already is.
- **Tests / register.** A facade-routes test for the new names (as
  `node/facade_routes_test.go`); no parity test (sealing is not matter.js
  behaviour); no `by_design.md` row expected — say so or add one.
- **Acceptance.** A host importing only `node`, `controller` and
  `contract` opens a sealed controller database and a sealed node store,
  rotates the key, and distinguishes a wrong key from a missing sealer.
- **Stays in go-fabric-server.** The key file and its flag, the operations
  text, the add-on option (server follow-up, #76).
- **Open.** One constructor in `node` or one per role; whether
  `docs/security.md` ("Sealing at rest", `:98-142`) should name the facade
  route as the host's way.
