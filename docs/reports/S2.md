# Report S2 — the bridge half, the S2 controller commands, by_design

Brief: [`notes/briefs/2026-10-25-S2-fabric-server-bridge.md`](../../notes/briefs/2026-10-25-S2-fabric-server-bridge.md).
go-fabric: **v0.11.0** (v0.12.0 did not appear during the work). Branch
`s2/bridge` from `main` at `v0.1.0` (`f1b2be0`).

## Bridge half

- **Transport** (`bridgeapi/api.go`, `conn.go`): `/bridge` on the same
  WebSocket server, envelope, codec, send path (`protocol.Conn`) and token
  rule; the bare `server_info` on connect, `{bridge_schema_version: 1,
  sdk_version, capabilities}`; requests concurrent (a `result` is never stuck
  behind a `declare`); events after `start_listening`, which holds the lock
  while it dumps, as `/ws` does.
- **Messages.** Host → node: `declare`, `set`, `host`, `remove`, `result`,
  `pairing_codes`, `node_info`, `start_listening`, `server_info`. Node →
  host: `changed`, `write`, `command`, `result_timeout`, `fabric_added`,
  `fabric_removed`, `commissioning_window`, `subscriptions`,
  `server_shutdown`. Shapes in `docs/protocol.md`, section "The bridge half".
- **The declaration decoder** (`declare.go`, `kit.go`, generated
  `clusters_gen.go`): `internal/gen` lists go-fabric's typed cluster packages
  (`go list -m` → `cluster/spec/*` with a generated definition and server,
  matched to the snapshot by their `Name`) and emits one
  `newKit[<c>def.Patch, <c>def.State, <c>def.Declare](<c>def.Name, <c>def.Wrap)`
  per snapshot cluster — 119 kits; the 16 clusters without a typed package
  (AccessControl, the Thread, camera, TLS and Joint Fabric clusters, …) are
  named in the file and refused by name. A patch is decoded key by key into
  the Patch's pointer fields (property name or Go name, case-insensitive;
  `null` into `Null` for a nullable attribute; nested members with
  `DisallowUnknownFields`); every error names its path
  (`devices[0].clusters.OnOff.initial.nope: …`). The Declare is filled by
  reflection: `Initial`, `Features` (titles or codes from the snapshot),
  `OnWrite` (a typed closure), `Handle<Command>` (`reflect.MakeFunc`).
  `device.New(device.Lookup(id), opts, decls…)`; its refusal is the
  `declare` error with the kit's message. The document is one
  `Aggregator.Batch`: add, replace a changed device, leave an unchanged one,
  remove an absent key, `MarkComplete`. The generator also writes
  `protocol/schema/declaration.schema.json` (`GET /schema/declaration`):
  name-keyed patches and cluster entries per typed cluster.
- **The opt-in events** (`hooks.go`): `handle_writes` installs the kit's
  `OnWrite`, `handle_commands` the named `Handle<Command>`s; each sends
  `write`/`command` with a correlation (a counter), `deadline` (RFC 3339) and
  `timeout_ms`, and waits for `result` until `--bridge-result-timeout`
  (5 s). Past it the controller is answered, the host gets `result_timeout`,
  a late `result` is refused. No listening client: refused at once; a
  disconnect answers what is pending. Without opt-in the kit applies writes
  and answers commands; `changed` (`OnChangedAsync`, every change whose
  origin is not `OriginHostSet`) tells the host.
- **One client.** A second connection gets `{error_code: 200, details: "the
  bridge half has a client: bridge1 from … since …"}` and close status 4409.
- **Daemon**: `--bridge` builds the bridge node (`node.New` with the half's
  `Observers`, store `bridge.db`, the test identity by default) and serves
  `/bridge`; `/health` adds `device_count`.

## Tests

In process with `fabrictest`, **both halves of the daemon in one
process**: the bridge half drives the site device's node
(`fabrictest.Device.Node()`, observers wired through `Topology.Configure`);
a daemon-built `node.New` cannot join a site (Q19). The controller half
drives the site's controller as in S1; the tests reach the node through
`/ws` — commission, `read_attribute`, `write_attribute`, `device_command`,
`attribute_updated` from the server's subscription. The site runs on the
wall clock (Decision D4).

- `TestBridgeEndToEnd`: ElectricalSensor + PowerTopology + EPM +
  PowerSource (the CE cookbook's shape) and an OnOffLight with
  `handle_commands: ["Toggle"]`; re-declare unchanged; the controller reads
  ActivePower 1234 and BatPercentRemaining 180; writes OnTime → `changed`
  `controller_write`; `On` → `changed` `command`; Toggle → `command`, `result`
  ok, second result refused; refused Toggle → the controller's error with a
  status; late result → `result_timeout`, controller answered, result
  refused; `set` ActivePower −600000 → the controller's `attribute_updated`;
  `host` reachable false → Reachable `attribute_updated`; `node_info`;
  `remove` → `endpoint_removed`.
- `TestBridgeWrites` (`handle_writes`: refused, accepted + `changed`, no
  host), `TestBridgeEvents` (`fabric_added`, `commissioning_window`,
  `subscriptions`, the dump of a reconnect), `TestBridgeOneClient`,
  `TestBridgeErrors` (17 declaration errors with their paths, the kit's
  refusals, 12 command errors, `host` statements, empty declaration).
- `kit_internal_test.go`: every kit reads and declares with every hook;
  patch decoding; wire names. Fuzz: `FuzzDecodeDeclaration`,
  `FuzzDecodePatch` (in `make fuzz-smoke`).
- `internal/daemon`: `TestRunBridge` runs the daemon with `--bridge` only on
  a Unix socket (linux; skipped on macOS/Windows), declares, reads the
  pairing codes, gets `server_shutdown`.
- The Python client (`examples/bridge-python/bridge.py`, 71 lines) was run
  once by hand against the daemon: server_info, declare (endpoint 2),
  pairing codes.

## Differences from the brief

- **Identify cannot be the host's.** The kit refuses `identifydef.Declare`
  on a bridged device ("the endpoint assembler mounts Identify (0x0003)
  itself", Q16). The end-to-end test uses `handle_commands: ["Toggle"]`;
  the Identify refusal is a `TestBridgeErrors` case.
- **A refusal reaches the controller as FAILURE**, not `Timeout` or the
  host's status: no facade error carries an IM status (Q15).
- **`host`** takes `name`, `device_address`, `channel_address` (Update),
  `reachable` (SetReachable) and `label` (Rename) — flat keys as in the
  declaration instead of an `addresses` object.
- **The device-type table** existed since S1 (`tables_gen.go`); the
  decoder resolves the name through it and `device.Lookup`.
- **`features`** in the cluster entry: the cookbook's ElectricalSensor needs
  them (PowerTopology, EPM, PowerSource).
- **Generator fix:** a derived cluster's inherited commands were no
  requests (RvcOperationalState's and OvenCavityOperationalState's Pause,
  Stop, Start, Resume): the snapshot states only the overridden parts; the
  direction, response and fields now come from the base. `/ws`'s
  `device_command` finds them too (changelog, Fixed).
- **`import_test_node`** stays S3 (not a pure cache operation).
- **The event name** is `subscriptions` (brief), not concept C.3's
  `subscription_count`.

## Decisions

- **D1** One generic kit per typed package, the Declare's hooks set by
  reflection: the generated file is one line per cluster, and everything it
  relies on is held by `TestEveryKitReads` against all 119 packages.
- **D2** `declare` is the whole topology (by_design B13).
- **D3** `changed` follows `Device.OnChangedAsync`: built on the device's
  goroutine after the change, never inside the server's change, so the
  server's lock never meets a cluster server's.
- **D4** Deadlines on the wall clock (`time.NewTimer`): in the daemon the
  node's clock is the system clock; the tests run a wall-clock site because
  the host's answer crosses a real WebSocket no site counter sees.
- **D5** `state` carries the attributes the server serves
  (`contract.ClusterAttributeLister`), by property name.
- **D6** The refusal of a second client is our own code 200 (the bridge
  half's codes start at 200) plus close status 4409.
- **D7** The bridge node's defaults are the public test identity (passcode
  20202021, discriminator 3840, vendor 0xFFF1/0x8001) with a constant salt,
  as go-fabric's embed-in-a-daemon guide does; `operations.md` says to
  change them. Declarations are not stored: the host declares after every
  connect; the endpoint numbers persist in `bridge.db`.
- **D8** `get_vendor_names` keeps the ledger's list a day and serves the
  stale list when a refresh fails.
- **D9** `controller/dcl` joins the import guard's facade list (brief §2
  names it).

## Left out

- Events a host emits (`Server.Emit<Event>`: a GenericSwitch press, …),
  composed devices (`Device.AddPart`), Aggregator partitions, host ports
  (`Sink`, …) and measurement sources in the declaration.
- Opening a commissioning window from the host (`node.OpenBasicWindow`).
- `attribute_names` / `get_schema` on `/ws` (S1's left-out list).
- An automated run of the Python client; the Apple Home pairing is the
  owner's manual step.

## Questions — facade gaps (go-fabric symbol needed, why)

- **Q15** No error type with an IM status on the facade: the dispatcher
  maps `im.StatusCodeError`/`im.MatterClusterStatusError`, whose method
  returns the named `im.StatusCode`. Needed: e.g.
  `contract.StatusError{Status, ClusterStatus}` (or
  `device.StatusError(status uint8, clusterStatus *uint8) error`)
  implementing both. Without it the host's `error.status` and a missed
  deadline (TIMEOUT) reach the controller as FAILURE.
- **Q16** `identifydef.Declare` is refused on a bridged device; the
  assembler's Identify takes no host handler. Needed: the assembler's
  Identify honouring a declared `HandleIdentify`/`HandleTriggerEffect` (or
  `device.Device.Identify() *identifydef.Server` for the mounted server),
  so a host can blink its device.
- **Q17** No hook for the node's subscription count: the half polls
  `node.Node.Subscriptions().Active()` every 5 s. Needed:
  `node.Observers.OnSubscriptionsChanged func(active int) error`.
- **Q18** No offline vendor table on the controller facade (matterjs-server
  ships `VendorIDs.ts`; go-fabric's `eligibility.VendorName` table is
  bridge-side and not a facade). Needed: e.g. a snapshot of the ledger's
  vendors in `controller/dcl/snapshot` (`Snapshot.Vendors()`), so
  `get_vendor_names` works without the network.
- **Q19** A daemon-composed `node.New` cannot join a `fabrictest.Site`
  (the site builds the node and wires its network and clock through seams).
  Needed: `fabrictest.Site.AddNode(cfg node.Config) *Device` (or
  `Site.NodeConfig()`), so the daemon's own composition is what the test
  runs; S2 tests the half against `fabrictest.Device.Node()`.
- S1's Q1–Q14 stand; go-fabric's bundle CJ closes them.
